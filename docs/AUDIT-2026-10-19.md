# Source and repository audit — 2026-10-19

This AI-assisted review covers the 0.5.0 source baseline, the 0.6.0 update system, the dependency changes merged through `56c1744`, and the subsequent avatar and Autopilot work in the release working tree. It combines source inspection, local fixtures, browser observations, dependency advisory checks and inspection of GitHub settings. The version-tag workflow separately enforces combined CI and release packaging before publication; consult the linked runs for delivery status. The findings below remain open until their linked issues meet their acceptance criteria; the report does not imply that every supported provider or operating system was exercised interactively.

## Corrections completed during the review

- Imported profiles now receive fresh, independent credential references and require deliberate rebinding. Custom CLI executable paths reset to the known provider default, imported MCP/script execution remains disabled, and automatic/platform chat replies start disabled. Regression fixtures verify that existing bots and installed resources retain their settings. This section omits sensitive reproduction details.
- Manual microphone startup now belongs to a capture session and bot. Late permission results, a bot switch, Stop or repeated starts invalidate stale capture and release its tracks; four local fixtures cover these races without accessing a microphone.
- Avatar rest and gesture axes derive automatically from skeletons instead of fixed legacy/modern signs or manual calibration. The ten OSA VRM-0 skeletons, a modern reference rig and the four coherent KayKit arm chains are covered by fixtures. The bundled Mage hides the alternate closed book and large staff without modifying the asset binary.
- GLB/VRM import now inspects container boundaries, supported VRM versions, JSON/file budgets, actual buffer/image resource references and required extensions before storing a model. Imported models are checked again when served, including legacy imports. Arbitrary `extras` metadata is not mistaken for a fetched resource. Two older bundled files with a non-aligned JSON block are handled automatically with a compatibility warning; this is not a claim of strict schema conformance. Unsupported model-audio extensions are reported, and animation-only VRMA files are rejected with an explanation. The [support matrix](AVATAR-SUPPORT.md) records the supported/partial/rejected cases.
- Authored body, eye, expression and morph tracks retain ownership during the animation pipeline. Humanoid transfer happens before the mixer, with one final VRM component update; constant or paused authored keys survive procedural resets. Existing mouth shapes remain audio-reactive during speech, without claiming phoneme recognition. Explicit idle-clip previews work when automatic idle is disabled, and WebGL initialization errors reach the feature panel. Speech now drives actual mouth/jaw shapes only; artificial speech body/head/arm motion and Nova's additional idle wobble were removed. Existing clips, intentional emotes and calm breathing/blinking remain. The generated capability catalog covers Nova and all sixteen binary assets; it does not claim that metadata alone proves a working expression or sound.
- The production OBS `/assets/{name}` route now distinguishes bundled JavaScript/CSS/fonts from canonical imported-avatar filenames. Frontend requests use the bundled resolver rather than the private avatar directory; invalid or incompatible avatar data is not passed unchecked to the browser renderer. Private canonical UUID-avatar requests also require the live session token, while public bundled JavaScript/CSS/fonts remain reachable without query parameters. This fixes the route collision that could prevent the packaged OBS frontend from loading.
- Autopilot activation is explicit and restricted to the Studio window. Saved/imported profiles cannot activate sessions; imported screen bindings reset. The scheduler waits before the first turn, postpones after activity/blocking and actual audio completion, permits one conversation lease, and selects due bots fairly. Defaults are 60–180 seconds and twelve attempts per rolling hour; failures and deliberate silence count, and Stop/restart does not reset the hour budget. Native admission also checks spacing, budget, active session and pending speech.
- Autopilot screen context uses one operator-fixed MCP tool name and JSON argument object, with the current bot's server/tool and model image grants checked again around the call. The model receives no general MCP/control routes or Skill-script execution. Choosing a genuinely observational tool remains the operator's responsibility; MCP software retains its own OS privileges. Real images use the existing bounded vision path. Cloud model, voice or memory services may receive their respective inputs and incur normal provider costs. Autonomous replies use the normal playback pipeline and never automatically post to Twitch or YouTube.
- Autopilot review corrections invalidate pending Start work on Stop, reject stale command completions, protect initial Studio/overlay snapshots and order runtime events by native revision and session seed. Tombstones survive Stop; passive events cannot authorize a new Studio session. Profile/document changes revoke old model snapshots and stop queued/playing autonomous speech. Per-attempt cancellation state is renewed so one failed playback does not poison later attempts. Existing automatic chat replies retain their own busy guard, and confirmed external output changes update the saved baseline without replacing local drafts.
- Profile export saves the current bot's settings and instruction documents first and aborts when saving fails.
- The new updater separates discovery from explicit download/install confirmation. Native checks restrict the caller and release destination, reject downgrades/prereleases, and verify package signatures and version binding. Unsaved edits and active capture/output block installation. Earlier releases require a manual bootstrap upgrade; Linux in-app installation uses AppImage.
- Main-branch protection now requires the three OS checks and dependency advisories, one approving review, an up-to-date branch and resolved conversations. Stale approvals are dismissed; linear history is required; force pushes and branch deletion are disabled. Administrator bypass remains available for recovery and explicitly authorized maintenance.

The fixes above do not close the distinct history, output-lifecycle or transactional-import findings below.

## Open bugs

All eight entries have the GitHub labels `bug`, `audit` and `priority:P2`. These are source findings; the linked fixture reproductions and acceptance criteria describe implementation checks and are not a claim that every scenario already has an executed regression test. They use delayed responses, mock transports and temporary data.

| Issue | Evidence and reproducible condition | Required result |
| --- | --- | --- |
| [#6 — Unpresented assistant history](https://github.com/ralphschuler/orbitpal/issues/6) | `agent::run` saves the assistant message before audio preparation; output invalidation does not remove that record. Cancel before playback, then reload history or start another turn. | Stage or mark pending replies; commit once on presentation and exclude cancelled/unheard replies from visible history and subsequent context, including after restart. |
| [#7 — Expired playback acknowledgement](https://github.com/ralphschuler/orbitpal/issues/7) | Studio `waitForPlayback` releases its wait after 180 seconds while the native speech entry can remain unfinished. An unavailable OBS output can leave native operations blocked. | Cancel the exact expired native job, reject late acknowledgements/audio and preserve other bots/newer jobs. Verify that output changes and updates become available. |
| [#8 — Per-job voice consistency](https://github.com/ralphschuler/orbitpal/issues/8) | Native `SpeechEntry` captures a voice; the external renderer's `speak` reads the current profile. Change the provider while a response is pending. | Use a public, credential-free voice snapshot consistently for the entire job; profile edits apply to subsequent jobs. Cover system/cloud transitions in each output path. |
| [#9 — Allocation limits on external reads](https://github.com/ralphschuler/orbitpal/issues/9) | MCP/CLI line limits are partly checked after complete-line allocation; the MCP HTTP JSON path is unbounded. Later text/image limits cannot bound those reads. | Apply byte budgets while reading stdout/stderr, HTTP JSON/SSE and catalogs. Reject oversized or incomplete input safely and preserve cancellation. |
| [#10 — MCP SSE framing and Unicode](https://github.com/ralphschuler/orbitpal/issues/10) | MCP SSE decoding is lossy per network chunk and parses individual `data:` lines. Splitting a multibyte character corrupts text; multiline events fail. | Preserve bytes until valid UTF-8/event boundaries; cover every split position, multiline data, comments, CRLF and multiple events while retaining limits. |
| [#11 — Transactional profile import](https://github.com/ralphschuler/orbitpal/issues/11) | `Store::import` can activate a profile or install resources before instruction validation/file writes finish. A later error leaves partial state. | Validate/stage the complete package and roll back failures. Invalid documents/assets and simulated write errors must leave active bot, registry, existing resources and files unchanged. |
| [#12 — Originating chat connection](https://github.com/ralphschuler/orbitpal/issues/12) | `ChatHub` connections are platform-global while outgoing replies use bot configuration. Two bots/accounts can combine a connection's chat destination with a different credential/configuration context. | Define connection ownership; preserve connection/channel/generation on queued messages and speech jobs. Reject stale/mismatched Twitch and YouTube destinations using mocked accounts. |
| [#13 — Audio cache byte budget](https://github.com/ralphschuler/orbitpal/issues/13) | The native speech cache permits 64 entries; each audio response can reach 25 MiB before base64. Completed jobs are not promptly released. | Enforce a total byte budget and eviction/release rules, preserving active-job retries. The approximately 2.1 GiB base64 ceiling is calculated from source limits, not measured usage. |

The SSE acceptance criteria follow the [WHATWG event-stream specification](https://html.spec.whatwg.org/multipage/server-sent-events.html#event-stream-interpretation) and [MCP transport specification](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports).
