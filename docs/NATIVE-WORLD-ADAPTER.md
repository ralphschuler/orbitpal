# Native World adapter

This is the private native renderer implementation for issue #72. Explicit Life start and actual page completion now feed a bounded native reconciliation worker, and its private document/measurement handlers are registered. Read-only semantic mirrors and the native movement/slot admission and transport are implemented as source, while actual desktop acceptance remains incomplete. The visual Life editor and ordinary session-window startup are available independently.

## Ownership and lifetime

Tauri owns the actual window constructor, session output lease, document authentication, physical layout, World context and action admission. The frontend renders a host-issued scope and reports new measured frames; it cannot create a session, replace a native owner or commit an arrival. Studio and OBS must eventually mirror the elected owner rather than acknowledge duplicate movement.

A retained Normal owner becomes Prepared, then Pending calibration, then Live after an accepted measurement and actual promotion. A later genuinely new frame is required before admitting an action. Cancellation is terminal. A revoked owner retains its charge and replacement barrier until actual restoration/retirement finishes. Dropping an asynchronous waiter does not complete cleanup.

Physical page completion is distinct from semantic document authentication. A fact-only asset probe pins one mount within its original five seconds and observes a current matching Avatar load for at most sixty seconds from that first pin. Repeated observations do not extend either bound. Same-key Avatar callers join the real pending load, including its eventual failure.

Only a consumed, one-use ready observation can rotate an operational document after exact old cleanup. The original pre-wait operator/UI/system cancellation atom and exact once-bound session lease are transferred unchanged; semantic rotation cannot manufacture a new admission watch. Stop followed by Start in the same window cannot reuse an old capability. Actual reload, replacement and retirement revoke the physical page lineage too. No capability appears in URLs, public events or persistent state.

One lifecycle worker per participant retains its charge until queued Main work really drains and exact physical cleanup completes. Hints and polls do not repeat a failed unchanged context. Genuine session, profile, page, UI/system or dialog transitions may reconcile again after their own clean admission. Preparing, stale and restoring owners block dialog scheduling. An exact healthy Live handoff may allow scheduling, but the generation-owned dialog must still cancel and restore every owner before strict dialog/playback admission succeeds.

Expected layout geometry callbacks are classified independently from semantic operator/profile invalidation. The owner's own move/resize must not cancel its document. Any unclassified/failed geometry observation still invalidates layout evidence.

## Bounds and locks

The original native preparation deadline remains issued+5000ms, including its documented inclusive boundary. Document first registration has its own original five-second bound; retries never retime either. A received frame must be genuinely newer and at most250ms old at admission. Live freshness is renewed only by accepted new frames, never metadata or a heartbeat.

Native cancellation registries use short locks and release them before Core, Store, GUI work or awaits. Physical owner handling precedes Core; Core→World→Store is the persistent action order. Action permit checks under that order read only frozen identities and cancellation atoms; they cannot re-enter an executor or GUI. No lock crosses an asynchronous Main-thread operation.

The frontend pins the full actor/World/stage/config scope from a current parsed native response. Events are hints until a fresh scoped read confirms the pose epoch. Old App reads and foreign events cannot retire a newer mount. At most one uncancellable read is outstanding, even after local timeout; each native generation has a fixed bounded read budget.

## Remaining qualification

The operator path now prepares one main-only, host-minted native intent from the actual retained owner. Its two-second monotonic deadline, original native permit, member, profile, session and local fence are checked again after OS/topology preflight. Point movement and host-resolved fixed-slot movement use the existing checked native action backend; no public mirror or UI renderer proof can create a native permit. Slot ownership remains ActionId-bound and is renewed/validated by the native transaction path.

Exact route capture separates Studio commands from native commands. Native delivery retains one bounded queue per actual member and validates Owned→Core before a fixed-deadline Main closure rechecks the same constructor, authenticated document, cancellation and visibility. Evaluating a command is only transport. Delivery, Start, progress and arrival still require new actual frames through authenticated native reports; no evaluation result is an action ACK.

The quiet Here rest retains its existing ten-active-second, zero-effect native dwell policy, now bound to the actual live output and native permit. A station move is still MoveTo. It does not fabricate a rest animation, chain into a rewarded station activity or claim arrival from a timer.

Idle native renewal retains the existing 3000ms cadence within the native Live owner's 5000ms accepted-frame lease, with the existing bridge's one-request/measurement-in-flight limits. Read-only mirror visibility requires that exact current Live route and an unexpired accepted binding; it does not require 100ms calibration. The separate 250ms bound still rejects a newly received measurement or action report that waited too long before host acceptance. Only genuinely new accepted frames renew evidence; metadata and timers do not. Actual resource measurements and native acceptance remain outstanding.

Studio and OBS consume read-only public canonical pose/activity data joined to the host's exact World/source/action identities. Studio creates no owner bridge for a controlled native actor. Scoped OBS feeds draw common objects only for the lexically first actor ID in the complete confirmed World snapshot, which includes every configured member even before Life/native readiness. This fixed display role stays independent of readiness within the exact World instance/stage/config revision. The designated feed must still satisfy its fresh exact visible native-owner row and the host's scoped object-election hint; neither the role nor that hint grants Ready or action authority. A sole non-designated feed has no automatic common-object fallback when the designated feed is absent or unavailable. Studio retains its one shared layer regardless of selected bot. This prevents same-scope readiness election from handing common objects between feeds; delayed packets across a different World instance or configuration are not an atomic network handover. These observations grant no action, capture or model permission. Exercise two actual Wry actors for sustained new frames, eight-direction movement and distinct reserved arrivals; cancellation/reload/replacement and normal speech handoff must finish through real cleanup.

Native desktop windows use the same fixed configured actor role for their common object layer. The layer joins a first confirmed scoped read of static anchors and complete configured membership to the exact current parsed native binding and mount; later pose hints do not replace that static configuration. Drawing requires the ready world view to be exposed, uncovered, free of a pending challenge, document-visible and matched to the full logical content viewport. Static object data adds no polling, independent expiry timer or read-budget reset, and never renews frame evidence or admits an action. Actual native object visibility, mixed-DPI mapping and lifecycle acceptance remain unproved.

Controlled owner, Core/Store, transport and renderer tests support the implementation but do not prove desktop visibility, actual window callbacks or compositor output. Native app acceptance, reduced motion, mixed DPI and Windows/Linux/macOS limits must be reported separately.
