# Everyday experience and declarative content

The Life stage stays the visual setup and explicit start point. Everyday preferences, social preferences and care settings are separate drafts with readback, revision checks, a shared save action and explicit discard. Navigating Studio keeps these drafts. A bot change requires saving or discarding them first. The implementation was substantially AI assisted.

## Preferences and interaction

`experience::Preferences` contains only saved choices. `ExperienceRuntime` holds process-only pause and pending impulse queues. Missing preferences inherit Stream for an existing profile with `autopilot.speak=true`, otherwise Focus. This preserves a profile's intended output policy without starting Life. Quiet and Focus deny unsolicited speech/text from every autonomous source; Stream still requires all existing activation, output, budget and privacy checks.

Studio requests pet, play, home and pause through `request_character_interaction`. The root native adapter uses the existing action executor and current native owner. UI feedback distinguishes admission from completion. These controls do not create screen, microphone, generic tool, provider or output permissions. The native avatar context menu and click-through restoration require separately qualified renderer integration; this Studio keyboard route is the fallback, not proof of that native interaction surface.

## Facts and album

Only crate-private native Store hooks record facts from actual confirmed transitions. `record_experience_native_snapshot` revalidates the exact immutable committed source against retained LIVE history in an IMMEDIATE transaction; later simulation checkpoints do not erase the witness. The strict latest-revision hook remains available for controlled current-state consumers. `record_experience_social_event` verifies both actual paired sources. Each fact needs stable actor IDs and native source event IDs. Use a stable distinct fact ID for each real transition (planned, started, completed, declined or cancelled). Never record offline reduction, restart recovery, guessed activity or model prose as a completed experience. No IPC inserts facts.

Facts start private, are deduplicated, limited to 256 per bot, and trimmed to 30 days on the next native event. Readback rejects corrupt/oversized data. The album groups only completed facts, without inventing empty days. Public preview includes explicitly shared facts only. Deletion/reset and explicit sharing are local Main operations. The real action commit queues a fresh Main `experience-state` projection before terminal job retirement. Optional persistence failures pause the owning session and get at most three bounded retries; a permanently broken optional Store cannot consume executor capacity indefinitely. Social structured memories remain bot-scoped and use their separate explicit sharing controls.

## Native platform impulses

The authenticated platform adapter may construct a `NativeImpulse` only after its actual channel connection, origin and current generation are verified. There is deliberately no renderer/viewer IPC that submits a native event. A platform adapter translates a configured closed trigger into greeting/play proposals or a bounded vote window; arbitrary chat text is never an authority or setting.

`ExperienceRuntime::admit_native_impulse` and `take_native_impulse` enforce current preferences/pause. Queues are isolated per owner, at most 16 pending, with 30-second maximum lifetime, bounded duplicate history and per-participant cooldown. Duplicate IDs stay duplicate across reconnect generations; a stale generation never executes. The root native consumer must recheck actual Life, participant availability, scene/action admission and speech priority before consuming a proposal. Focus, pause, Stop and profile/route changes cancel pending proposals. No queued proposal grants activation or implies completion. Actual Twitch/YouTube channel qualification remains separate from these controlled policy tests.

## Content packages

The example `public/content-packs/desk-garden.json` adds a character template, toy, existing-capability motion mapping and bounded activity as data. Preview validates a complete manifest through the same native parser used for installation. An installed pack starts inactive. Activation is an explicit revision-checked operation and does not start Life.

Schema/runtime version 1 accepts only closed actions/conditions, validated namespaced IDs, bounded weights/durations, declared dependencies and built-in model references. It does not accept file paths, remote assets, scripts, executable code, arbitrary effects or extra permissions. The package extends data and existing supported capabilities; importing new binary model assets continues through the existing explicit avatar importer. The preview lists actual templates, object offers, dependencies and local resources. There is no hidden download.

The native planner consumes exact active manifests and retains package ID, manifest version, catalog revision and the chosen behavior definition on each real job. New or changed visual references are validated inside the same World-save SQLite transaction; unchanged missing or inactive references remain visible and editable. Current object offers map to existing typed native actions, never Ready, a lease or an ACK. Conditions use confirmed needs, eligible behaviors compete by bounded weight, and declared duration raises the actual measured station dwell. The current station adapter accepts idle or an explicitly declared idle fallback; unsupported clips are unavailable. Actual rewards remain the operator-configured domain effects after a successful executor commit. Deactivation commits the revision-checked inactive state while holding the actual Core admission lock, synchronously revokes every dependent job token, cancels coupled social work and polls exact reservation cleanup before releasing the lock. Every Plan and later non-cancellation phase rechecks the frozen active definition in its own Life SQLite transaction. Reactivating the same version cannot revive an old catalog revision or cancelled job. A dependent active pack blocks removal of its required dependency. Upgrades require prior deactivation and a strictly newer manifest version. Unsupported schemas are rejected explicitly; saved references are preserved for fallback or pause rather than silently rewritten. Actual animated package qualification remains a native integration check.

## Desktop geometry boundary

The capability projection distinguishes a compiled macOS numeric geometry provider from an actual qualified sample. Unsupported platforms explain the manual visual-anchor fallback. It can always turn off an already-saved opt-in. `desktop_affordances::GeometryLease` is a short-lived pure mapper for the genuine native source described below. It stores no geometry on disk, no window names/content and no image. A source generation/display join, physical work area, nonregressing time and 1.5-second freshness gate every anchor. Uniform physical DPI scaling preserves canonical positions; negative monitor origins are supported. Cursor proposals additionally require Stream and separate opt-in. Unknown/expired/lost source produces no anchors. A native platform provider and real platform acceptance are still required; no foreign-window input or manipulation belongs to this feature.

- `storage.rs`: `#[path="experience_store.rs"] mod experience_store;` as a child so bounded SQLite methods keep the existing Store ownership.
- Register `experience_commands::{get_experience_snapshot,set_experience_preferences,set_experience_pause,request_character_interaction,delete_experience_fact,set_experience_fact_shared,list_content_packs,preview_content_pack,install_content_pack,set_content_pack_active,delete_content_pack}`. Main/updater checks are in the wrappers; the root operator classifier must permit only the appropriate read/write surface.
- The async preference/pause hooks return `Result<(),String>`; `set_content_pack_active_native` is synchronous and returns the actual updated catalog. Changed settings immediately cancel incompatible pending work; no resume or native receipt is fabricated. Persisted choices remain authoritative if an invalidation reports an error.
- Implement async `request_character_interaction(&AppHandle,&str,&InteractionRequest)->Result<Value,String>` using the existing executor. Closed result: `{version:1,botId,kind,status:'accepted'|'declined'|'waiting'|'cancelled',reason:null|'busy'|'resting'|'unavailable'|'operator'}`.
- Record native confirmed facts through the Store hook and publish a new Main projection. Consume native platform impulses through the runtime only after real origin validation. Unwired hooks must fail truthfully, never return a simulated success.
- Care UI uses root's `get_life_care_preferences`/`save_life_care_preferences`, including `restoreUnits`. It never applies rewards itself. Social UI uses the agreed bot-scoped `social_commands` endpoints; its writable development projection preserves earned hobby/goal progress.

Focused frontend tests cover scope/validation, phase distinctions, explicit public sharing, recap aggregation, care numerical bounds, social development/routines, Snack wire/editor presence, localization and absence of authority-grant calls. Full native/frontend/build checks are centrally batched after shared integration. No actual host GUI, provider/channel or native acceptance was exercised by this branch's author.

## Native context menu and macOS provider follow-up

`native_interaction` uses an actual Tauri system menu attached to the retained native character window. It never sets focus, window bounds, top policy or cursor-ignore. This avoids turning the full-workarea transparent output into an input surface. The root owner factory supplies the actual retained window, its WindowSignals, exact route/binding scope, a local physical popup point and a current-ownership predicate. A native menu item is a single-use operator choice, revalidated before the existing action adapter runs. Dismissal/Escape performs no action; a 15-second nonce-bound lease, exact-window blur/close/destroy callback and root Stop/route cancellation retire late choices. Retiring an old constructor cannot cancel a replacement constructor's menu. Native menu keyboard behavior and OS acceptance remain to be qualified.

Root adds `mod native_interaction`, manages `NativeInteraction::default()`, calls `native_interaction::install(app)` once after managed state exists, and registers `open_native_character_menu`/`close_native_character_menu`. Supply `life_runtime::native_interaction_owner(app,bot)->Result<MenuOwner,String>` using the actual native constructor/binding/local fence. `MenuOwner::new` takes bot, retained WebviewWindow, scope, retained WindowSignals Arc, local physical point and an Arc current-predicate. Stop/route cleanup calls `native_interaction::cancel(app,Some(bot))` outside Core/Store locks. The small overlay event hook uses exact signals for blur/close/destroy. Safety closure remains available to the exact avatar window; only Main may open a menu. The Studio component does not synthesize a native menu event.

The macOS geometry provider reads only `CGWindowBounds`, numeric owner PID/layer, on-screen status and current `NSEvent.mouseLocation`. It never reads window titles/owner names, pixels, event taps or input APIs. Apple describes [window bounds in top-left screen space](https://developer.apple.com/documentation/coregraphics/kcgwindowbounds) and [mouseLocation as current screen coordinates](https://developer.apple.com/documentation/appkit/nsevent/mouselocation). Its display join follows the locked Tao 0.37.1 monitor formula: physical origin and resolution from Quartz screen bounds/CGDisplayPixels multiplied by the actual native scale. A unique exact match is required; ambiguous/mismatched display layouts yield no proposal. AppKit mouse Y is converted relative to the actual primary display, then mapped through that matched display into the exact current physical scene frame. No extra Cargo dependency is required.

Root calls `desktop_affordances::read_native(&ReadContext,&Preferences,paused,now)` on Main only, after AND before rechecking the actual current scene/fence. `ReadContext` contains native generation/display ID, actual full physical display, actual scene physical rectangle and native scale. The provider enforces main-thread use, explicit independent opt-ins and bounded geometry. Feed its sample to the existing ephemeral GeometryLease and use only proposals that still join the same live generation/display/safe region; loss immediately returns to fixed anchors. macOS reports `native_provider` support, distinct from a successful sample; Linux/Windows still report unavailable. Real monitor moves, mixed DPI, Space/lock changes, cursor play and platform acceptance remain unproved.

The durable album hook is now `record_experience_life_fact(bot,expected_revision,event_sequence)` rather than accepting ActivityFact. Its IMMEDIATE transaction reads the existing validated Life store, exact latest live committed event, current action ID/phase, simulation time and native saved time; all fact fields and source IDs are derived. Offline, restart and guessed records cannot become completed experiences. The immutable native retry hook also accepts a later actual checkpoint only while the identical LIVE source event remains in the same actual lineage and retained history. `record_experience_social_event(bot,&SocialEvent)` derives only completed paired facts, rechecking the exact committed social memory and BOTH actual persisted completed actions/live source events inside its transaction. Both start private and deduplicate. A single actor's move/look are labelled honestly, rather than interpreting any movement as going home. The root real transition observer is still the only caller; SQLite provenance is not a replacement for real native action qualification.


## Sealed Twitch and YouTube receive adapter

`platform_impulses` receives only from the existing authenticated native chat loops, after their actual channel-route, message ID, origin and own-message filters. It accepts exact plain-message commands `!orbit hello`, `!orbit play`, `!orbit vote rest`, and `!orbit vote play`. Other text, notifications and missing/old timestamps do not become proposals. Vote commands participate in an actual native 15-second tally, described below; only a winning result becomes a proposal. Raw provider IDs are hashed into stable platform-scoped IDs; no message, sender or credential is added to the impulse queue.

Admission requires a real active, unpaused Life-mode session owned by the connected bot, explicit Stream opt-in, and the saved participant allowlist. The current session ID and native connection generation are retained. The actual pulse validates every retained source against ChatHub and the current saved owner binding before consuming. Connection teardown, replacement, native disconnection and Drop synchronously cancel all weak-bound native jobs for that exact source. Finishing a native job sets only its own flag; it never cancels the connection. Each source bounds the weak registry to 64 live jobs and prunes completed or dropped jobs.

Root declares `platform_impulses`, manages `PlatformImpulses::default()` and calls `platform_impulses::pulse(app)` from the actual native pulse outside Core/Store locks. Its async `life_runtime::consume_platform_impulse(app,owner,&ImpulseKind,&[String],&DispatchLease)->Result<(),String>` checks `authority.current(store)` and `authority.session_id()` against the current real native Life session under admission. It creates its own job-cancel Arc and calls `authority.bind_cancel(&job_cancel)` before the first await, retains that token through real plans/delivery/frames, and rechecks source/profile/session immediately before actual admission and inside the existing transaction cancellation fence. The proposal deadline is anchored once to native monotonic time at dispatch. A frozen native source fence rechecks that deadline, connection and exact owner profile in the same actual Plan and phase SQLite transactions, including after database waits. Expiry cancels the exact dependent action; it never fabricates completion or refreshes the event lifetime. No reply, activation, generic tools, permissions or manual ACK route is introduced.

The Studio reads bounded queue counters while visible without overwriting an unsaved draft. “Added to queue” is admission to the proposal queue, not proof of execution or completion. Actual Twitch/YouTube receive-to-native execution and OS/platform acceptance still require separate qualification; authored native fixtures exercise source/owner/session/cancellation policy only.


## Active templates in the visual editor

The object tray projects only actually active catalog entries. Adding one creates an ordinary bounded visual object and seat with `contentRef:{packageId,packageVersion,templateId}`. Drag, keyboard movement, save and readback preserve that exact reference. A missing or inactive template keeps its saved reference and ordinary fixed placement, labelled as unavailable; it is never silently rewritten to another package version. When the same object ID and kind exist in a newer active version, the inspector offers an explicit version migration. It changes only the draft reference, preserving all positions and seats, and still requires the ordinary revision-checked save. Renamed or incompatible objects require an explicit replacement rather than a guessed migration. The host must resolve the exact active compatible version before offering package-specific work. Neither an imported reference nor a visual draft activates a package or creates native action authority.

An active character template has an explicit “Create character” action. `create_content_pack_character` is Main-only, updater-idle and generation-idle. The Store reserves a fresh profile directory, then revalidates the exact active template inside the same IMMEDIATE transaction that inserts the new bot and initial sociability/rest-preference values. It leaves the currently selected profile, actual Life sessions and all prior bot data unchanged. The fresh profile uses only the manifest’s allowed built-in avatar; credentials, API defaults, MCP/Skills/scripts, screen context, wake word, automatic replies, voice output and unsolicited speech are not inherited or enabled. Failure removes only the newly reserved UUID directory. The operator chooses the new bot from the ordinary list and adds it to the visual stage before an explicit Life start.

Root registers `experience_commands::create_content_pack_character` and supplies the shared typed `content_packs::ContentRef` on Rust anchors/profile provenance. The social seed hook initializes only two bounded traits in the same creation transaction, without memories, relationships, hobby progress or sessions. The native package planner now resolves and binds these references through real slots, plans and phase transactions. Actual animated package qualification through the current native surface still remains separate from controlled tests.


## Bounded native vote windows

`platform_votes::Window` is the production tally used by the real receive adapter. Each owner/platform/actual route/Life session has at most one 15-second window, with two fixed choices (rest/play), at most 256 native sender hashes and 256 provider-event hashes. Twitch uses its actual `chatter_user_id`; YouTube uses its actual author channel ID. Missing/malformed sender identities cannot vote. IDs are platform-scoped hashes, kept only in this ephemeral tally; no sender name, message, raw identity or ballot is returned to Studio, logged or stored. The existing native receive deduplicator still precedes the adapter.

The first accepted message fixes the deadline. More messages never reset it. A sender and a provider event can each vote only once per window. No winner is emitted before closing, after any contributing accepted message expires, on a tie, for an empty window, or after clock regression. A first message must have enough real provider freshness left for the full window. The retained winner expiry is the earliest accepted ballot expiry, never a refreshed timestamp. A winning result enters the same 16-item proposal queue, current participant allowlist, cooldown and real native admission path; it neither starts Life nor confirms that an activity completed.

Source/route replacement, real Life session changes, Stop/pause, preference changes and unavailable connections retire pending windows. Different owners and platforms keep separate counts; votes are not combined across unverified identities or channels. There are no channel posts or outgoing poll APIs. Studio sees only platform, two bounded counts and the remaining time at its last actual read, through the existing read-only experience snapshot. The actual native consumer signature and separate weak-bound job cancellation stay unchanged. Native tally/source fixtures are local controlled cases; real provider polling, channel delivery, native actions and visual qualification remain unproved until separately exercised.
