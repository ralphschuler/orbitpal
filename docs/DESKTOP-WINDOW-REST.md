# Optional window-edge rest

Desktop geometry requires its separate saved opt-in and an explicitly started native Life actor. A window target first uses the ordinary zero-effect MoveTo pipeline. Only its exact confirmed Completed action, the same current World position, an allowed rest animation and a still-current native station-capable output can propose Rest Here. Proximity, a timer, a planned move and a cursor target cannot start rest.

The macOS provider retains only numeric window number/owner, rectangle, display and time in RAM. No window name, content, screenshot, input, filesystem record or exported window identity is added. A replacement window with the same rectangle fails the identity check. Unsupported platforms continue to offer the ordinary manual visual anchors.

`desktop_places::WindowRestGuard` is cloned into the actual native job. The shared host must bind its own cancellation atom before awaiting and check `current(bot, output, now)` at admission and inside every non-cancellation Plan/phase SQLite closure. This check is synchronous and cannot enter Core, Store or the GUI. The executor still requires actual accepted renderer frames and the existing rest dwell minimum before completion can restore needs. This is ordinary bounded Here-rest policy, without inventing an object slot or station lease.

Real geometry reads continue while rest is pending. One retained Main-read slot bounds queued and running geometry probes across all actors. The queued callback owns that slot until it actually completes or is dropped, so a timed-out caller cannot stack new probes behind a blocked Main thread. The 500ms bound concerns queue/result admission; an executing synchronous OS call cannot be preempted by that timeout. A matching sample can advance the retained sample time; a pulse, repeated timestamp or renderer event cannot. The sample must be at most 1.5 seconds old. Observed move/close/replacement, unknown geometry, stale/regressing time, reduced motion, opt-out, changed preferences, DPI/output/session loss and Stop permanently invalidate that job's guard and cancel its exact action. A later matching sample cannot revive it. Sampling cannot establish that a third-party window stayed unchanged between native observations; the bound is freshness of actual observations, not continuous OS tracking.

The controlled source regressions exercise real domain Plan/Start/Complete transitions, identity replacement, freshness renewal and sticky cancellation. They do not create a native Ready receipt or prove OS behavior. This branch's author has not run those tests, native builds or GUI acceptance; shared host integration and central gates remain required.
