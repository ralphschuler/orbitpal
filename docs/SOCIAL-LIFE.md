# Social Life and character development

Social scenes use two explicitly started desktop Life participants on the same current World. The native host chooses two currently offered places on one object, invites the guest, and waits for its decision. The coordinator's phases are invitation, accepted, resources reserved, approach, execution and a terminal outcome. Each actor stays exclusive until actual action cancellation and reservation cleanup complete. A visible invitation, a reservation and an animation start do not count as shared success.

Approach and execution use the production native action executor. Both exact action IDs must reach actual committed `Completed` events. The paired SQLite transaction checks the two retained committed event IDs, actor identities and Life lineages before writing either actor's relationships, memories or progress. A later real action does not erase an earlier retained completion witness. Lost history fails closed. Stop, a changed session, removed World membership, changed output/topology, an unavailable native view, a declined invitation and timeout cancel the scene. Restart records pending scenes as interrupted and restores no session or resource lease.

Each bot has separate directed familiarity and affection, three bounded hobbies, numeric traits and interests, soft time preferences and at most one small goal. Native successful activities earn progress once; invitations, cancellations and offline time do not. Goals can pause when their actual opportunities disappear. Interests and routines influence proposals; they never reserve resources or authorize actions. The operator can edit preferences, discard a goal, reset development, inspect memories, delete them and explicitly share a structured memory. Sharing contains only the closed event kind, outcome, participant IDs and timestamp. It does not expose another bot's chats, persona, documents or grants.

The existing bot-bound SQLite file holds these records. Memories retain 128 rows per actor with bounded counters for older outcomes; scene history retains the latest 64 terminal scenes plus bounded active scenes. A fixed typed phase trace retains at most 16 distinct phases per scene; snapshots expose at most 256 trace rows. The trace records protocol order; its `atMs` remains the scene's invitation time, not a claimed measurement of every phase's duration. Context retrieval uses one claimed own or explicitly shared event, or a current local goal, rather than a generic prompt. Deletion or preference changes invalidate pending contexts.

Optional model dialogue is off by default. Both participants must allow unsolicited output and explicitly enable model dialogue. The conversation has at most four turns and lasts at most 60 seconds; its default is two turns and 30 seconds. Each turn uses an existing native speech claim, rolling admission budget, Stop cancellation, OS availability checks, request-local approved screen context and durable provider accounting. Only its own knowledge and an event-specific memory query are available; peer private histories and personas are absent. Replies are buffered, have no tools and must match the closed short-text/reaction schema. Actual presentation acknowledgement advances the conversation. Model return alone does not.

The dialogue policy also reserves a conservative token total and an estimated monetary total before requesting a model. A rate is explicitly supplied by the operator in microcurrency units per million tokens. It is a planning estimate, not a provider invoice guarantee. Unknown model token bounds or absent rates use the local fallback. Daily estimate reservations survive restart and do not refund an ambiguous send. The installation's normal request/token/image/TTS budgets remain independent and apply as well. Local fallback is available in German, English, French and Spanish and creates no implicit paid speech synthesis. Quiet and Focus suppress unsolicited text and voice.

The native speech scheduler and its existing rolling cadence remain authoritative. A genuine completed scene can wake an opportunity but cannot bypass admission spacing. Local fallback uses a separate native local-text claim, including when no model is configured. It retains the same explicit Life session, speech opt-in, actual OS/UI/output gates, rolling admission and presentation acknowledgement; it grants no cloud authority. Model turns first perform the existing native-to-normal output handoff. Expiry or Stop never revives a turn through fallback. No social module claims actual cross-platform native rendering or issue #72 acceptance from controlled domain or SQLite tests.
